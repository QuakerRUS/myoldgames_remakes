# Keyboard Simulator: layout file (`keyboard-simulator/data/layout/ru.json`)

The on-screen keyboard of Keyboard Simulator: the physical keys, the characters of the Russian
(ЙЦУКЕН) Windows layout on them, the finger that presses each key and the Shift to hold for
the shifted characters. Geometry is given in key units, not pixels: the renderer scales it.

Generated by `python -I tools/import/kbsim_layout.py` (see "Origin" below); read by
`kbsim::Layout` (`keyboard-simulator/core`).

## Encoding

UTF-8 without BOM, LF line endings, standard JSON. The generator writes one key per line.

## Top level

| Member | Type | Meaning |
|---|---|---|
| `format` | string | always `"kbsim-layout"` |
| `version` | number | always `1` |
| `name` | string | display name, `"ЙЦУКЕН"` |
| `language` | string | `"ru"` |
| `fingers` | array | the nine fingers, informative (see below) |
| `rows` | array of arrays | keyboard rows top to bottom; each row is an array of keys left to right |

### `fingers`

| Member | Meaning |
|---|---|
| `id` | `left_pinky`, `left_ring`, `left_middle`, `left_index`, `thumbs`, `right_index`, `right_middle`, `right_ring`, `right_pinky` |
| `hand` | `left`, `right` or `both` (the two thumbs are one finger: the space bar takes either) |
| `legend` | the digit of the finger legend of the original picture, "5 4 3 2 1 / 1 2 3 4 5" |
| `original_colour` | the colour of this finger's keys on the original `bg.bmp` |

Original colours (mean RGB of the keys on `bg.bmp`, for reference; the remake may choose its
own palette, but the original shares colours between hands):

| Colour | Approx. RGB | Fingers |
|---|---|---|
| green | 195 223 195 | left pinky, right middle |
| yellow | 233 233 178 | left ring, right ring |
| lavender | 195 195 223 | left middle, right pinky |
| pink | 231 210 231 | left index |
| cyan | 214 233 233 | right index |
| grey | 220 220 220 | thumbs |

## Keys

| Member | Required | Meaning |
|---|---|---|
| `code` | yes | physical key, W3C `KeyboardEvent.code` name (`KeyQ`, `Digit1`, `ShiftLeft`, `Space`, ...); maps 1:1 to SDL scancodes. Unique. |
| `normal` | no | the character typed without Shift (exactly one character) |
| `shift` | no | the character typed with Shift (exactly one character) |
| `label` | no | caption to draw. Letter keys carry the capital letter (`"Й"`), modifiers their name (`"Backspace"`, `"Tab"`, `"Caps Lock"`, `"Enter"`, `"Shift"`, `"Ctrl"`, `"Win"`, `"Alt"`, `"Menu"`), Space an empty string. Symbol keys have no label: draw `normal` (bottom left) and `shift` (top right). |
| `width` | no | width in key units, default `1`; the height of every key is 1 |
| `finger` | yes | one of the finger ids above |
| `home` | no | `true` for the home-row keys ФЫВА ОЛДЖ |
| `bump` | no | `true` for А and О (the keys with a tactile bump) |
| `shift_with` | if `shift` | `code` of the Shift key to hold for `shift`: always the Shift of the opposite hand (`ShiftRight` for left-hand keys, `ShiftLeft` for right-hand keys) |

Rules checked by the loader: every character appears on one key only; every key with `shift`
has a valid `shift_with`; `finger` is a known id. The x position of a key is the sum of the
widths of the keys to its left. Every row of `ru.json` is 15 units wide.

## The layout

```
Row 0  Ё   1!  2"  3№  4;  5%  6:  7?  8*  9(  0)  -_  =+  Backspace(2)
Row 1  Tab(1.5)  Й Ц У К Е Н Г Ш Щ З Х Ъ  \/(1.5)
Row 2  Caps Lock(1.75)  Ф Ы В А П Р О Л Д Ж Э  Enter(2.25)
Row 3  Shift(2.25)  Я Ч С М И Т Ь Б Ю  .,  Shift(2.75)
Row 4  Ctrl Win Alt (1.25 each)  Space(6.25)  Alt Win Menu Ctrl (1.25 each)
```

Fingers (as coloured on the original picture, which follows standard touch typing):

| Finger | Keys |
|---|---|
| left pinky | Ё 1 Й Ф Я, Tab, Caps Lock, left Shift, left Ctrl, left Win |
| left ring | 2 Ц Ы Ч |
| left middle | 3 У В С |
| left index | 4 5 6 К Е А П М И |
| thumbs | Space, both Alt |
| right index | 7 Н Г Р О Т Ь |
| right middle | 8 Ш Л Б |
| right ring | 9 Щ Д Ю |
| right pinky | 0 - = З Х Ъ \ Ж Э . Backspace Enter, right Shift, right Win, Menu, right Ctrl |

The 95 characters of the layout are exactly the 95 glyphs of the original program
(А–Я, а–я with Ё/ё, space, digits, `- = ! " № ; % : ? * ( ) _ + \ / . ,`).

## Origin

`tools/import/kbsim_layout.py` holds the physical description (rows, codes, widths, characters)
and derives or verifies everything else from the 2007 program in
`archive/diplom-2007/program/Data`:

- `diplom.dat` part 1 — 97 records of four little-endian `uint16` (x1, y1, x2, y2): the key
  rectangle on `bg.bmp` for each glyph (0–32 А–Я with Ё at 6, 33–65 а–я with ё at 39, 66 space,
  67–75 digits 1–9, 76 digit 0, 77–94 `- = ! " № ; % : ? * ( ) _ + \ / . ,`), 95 left Shift,
  96 right Shift. The script checks that the rectangles form the same rows in the same order.
- `diplom.dat` part 2 — 95 bytes, the character `getch()` returned on a QWERTY layout for each
  glyph. The script checks it against the physical keys; glyph 76 records `:` instead of `0`
  (the bug that made `0` impossible to type in the original) and is reported, not used.
- `bg.bmp` — the hue of each key gives the finger pair (see the colour table) and the side of
  the boundary between the pink and the cyan keys of the row gives the hand. Keys without a
  rectangle in `diplom.dat` (Tab, Caps Lock, Enter, Backspace) are sampled at fixed points.
  The Ctrl/Win/Alt row is not on the original picture (its place holds the finger legend);
  it gets the standard fingers. Ё/ё share one rectangle, as do the two characters of every
  symbol key.
